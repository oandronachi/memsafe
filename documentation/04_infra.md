# Build & TestInfrastructure

The build & testing infrastructure is the `run-test-infra/` source tree. It provides a self-adjusting Python runner over a generic CMake/CTest project: `python tools/run_tests.py --backend auto` is the TL;DR command, and the runner selects local, WSL, Docker, then Podman in order. Forced backends report their own failure; auto mode falls back only on classified backend-infrastructure failures and stops on real validation failures.

The build remains generic and drop-in. CMake discovers headers, runtime tests, examples, and compile-fail tests by convention, while all library-specific choices live code-side in `testing/infra_lanes.json`: C++ standard, build type, sanitizer flags, preprocessor defines, optional source/exclude globs, optional test launchers, and optional container image refs. The default lanes are dependency-free (`debug`, `release`, `asan-ubsan`, `cxx17`); heavier F2 categories are wired as non-default optional lanes (`tsan`, `msan`, `hwasan`, `valgrind-cxx17`, `property`, `fuzz`, `concurrency`, `perf`) without requiring their dependencies for a green baseline.

Compile-fail tests use in-source `// INFRA_EXPECT_FAIL: <regex>` metadata and a generic `testing/cmake/expect_compile_fail.cmake` driver. The driver fails if the target unexpectedly compiles, and when a regex exists it requires the diagnostic to match. A7 stabilizes GCC/Clang-family diagnostics with `LC_ALL=C`/`LANG=C`; MSVC/clang-cl tests should key regexes on stable diagnostic codes such as `C2280` and `C4834`.

AI/CI output is stable: the runner always emits a final `SUMMARY` line and writes `testing/build/summary.json` with `schema_version`, `tool_version`, backend, `image_ref`, requested lanes, lane verdicts, and fallback reasons. CTest JUnit XML is emitted per lane when the available CTest supports `--output-junit`; lack of that optional XML feature does not fail the run.

The produced source tree is source-only. Generated `testing/build/**` and `__pycache__/**` are excluded, and `tools/clean.py` removes them. The bundled `include/memsafe/*`, examples, and tests are a removable smoke fixture only; the real library contract remains F1/F2/F3, not the fixture implementation.

To use this infrastructure, (1) on a machine with CMake + CTest + a C++ compiler (or Docker/Podman/WSL), run `python run-test-infra/tools/run_tests.py --backend auto` and confirm the final line reads `result=OK`; (2) run `python run-test-infra/tools/clean.py` once to clear any stale generated `testing/build/`/`__pycache__/` content currently in the tree; (3) when the real header-only library and its tests exist, drop the headers under `include/`, runtime tests under `testing/tests/`, must-not-compile tests (with their `// INFRA_EXPECT_FAIL:` directives) under `testing/tests/compile_fail/`, and examples under `examples/`, optionally adjusting `testing/infra_lanes.json` lanes — no edits to the tool are required; (4) delete the barebones fixture wholesale whenever the real implementation supersedes it.
