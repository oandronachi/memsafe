A header-only C++20 (with a C++17 mode) library that brings **partial, Rust-like memory safety**
to ordinary C++: move-only ownership, runtime borrow checking, generational handles, RAII scopes,
and thread-safe wrappers — with a configurable violation policy and **no new compiler or runtime**.

> **Status:** v1. Partial-safety by design — it reduces use-after-free, double-free, and invalid-borrow
> bugs, but it is **not** a full borrow checker and does **not** guarantee data-race freedom. See
> [Scope & non-goals](#scope--non-goals).

---

## Why

Roughly 70% of CVE-class vulnerabilities in large C/C++ codebases are memory-safety issues, and they
have stayed there for over a decade. Rewriting in a memory-safe language is often infeasible. `memsafe`
takes the pragmatic middle path: opt-in wrapper types that enforce ownership and borrowing **at runtime**
(checks that compile away in release), so you can harden the risky parts of an existing C++ codebase
without changing toolchains.

## Features

- **Ownership** — move-only `Owner<T>` with `noexcept` move (safe in `std::vector`); non-owning
  `Ref<T>` / `MutRef<T>` borrows with runtime exclusivity checks, both `[[nodiscard]]`.
- **Generational handles** — `Slot<T>` / `Handle<T>` / bounded, lock-free `SlotMap<T, N>` detect
  use-after-free via per-slot atomic generations (Treiber-stack free list, no global mutex).
- **Scopes** — `Scope`, an RAII arena that destroys everything it created, in reverse order.
- **Concurrency** — `SyncOwner<T>` / `SyncRef<T>` / `SyncMutRef<T>` (atomic borrow counters),
  `Arc<T>` (atomic shared ownership), and `Mutex<T>` (hands out a `MutRef<T>` via `lock()`).
- **Configurable violation policy** — abort (default), throw, or a user handler — chosen at compile time.
- **Zero-cost in release** — all checks compile away when `MEMSAFE_RELEASE_CHECKS=0`.
- **Optional back-end hooks** — emit Clang `lifetimebound`, CHERI, or Rusty-C++ annotations when enabled.
- **Portable & header-only** — single umbrella header, C++20 baseline, C++17 compatibility mode.

## Requirements

- A standards-conforming **C++20** compiler (GCC, Clang, or MSVC), **or C++17** with
  `MEMSAFE_CXX17_COMPAT=1`.
- Nothing to build or link — the library is **header-only**. (The test harness uses Python 3.8+ and
  CMake; see [Building & testing](#building--testing).)

## Installation

Copy the `include/` directory into your project (or add it as a submodule) and put it on your
compiler's include path, then include the umbrella header:

```cpp
#include <memsafe/memsafe.hpp>   // everything
```

…or pull in just what you need: `<memsafe/owner.hpp>`, `<memsafe/handle.hpp>`, `<memsafe/scope.hpp>`,
`<memsafe/sync.hpp>`, `<memsafe/violation.hpp>`, `<memsafe/backend.hpp>`.

## Quick start

### Ownership & borrowing

```cpp
#include <memsafe/owner.hpp>

memsafe::Owner<std::string> title(std::string("daily"));   // move-only, owns the value
title.has_value();                                          // true

{
    memsafe::Ref<std::string> a = title.borrow();           // immutable borrow (copyable)
    memsafe::Ref<std::string> b = a;                        // a second reader is fine
    // *a == "daily"
}                                                           // borrows end with their scope

{
    memsafe::MutRef<std::string> w = title.borrow_mut();    // exclusive borrow
    w->append(" grind");                                    // requesting this while a Ref is
}                                                           // live triggers the violation policy

memsafe::Owner<int> src(42);
memsafe::Owner<int> dst(std::move(src));                    // ownership moves; src.has_value() == false
```

### Generational handles (use-after-free detection)

```cpp
#include <memsafe/handle.hpp>

memsafe::SlotMap<int, 2> values;            // fixed capacity = 2
auto h1 = values.allocate(10);              // SlotMap<int,2>::handle_type
auto h2 = values.allocate(20);

const int* p = values.get(h1);              // generation-checked lookup -> *p == 10
values.deref(h2) += 2;                       // 22

values.deallocate(h1);                       // slot freed; h1 is now stale
auto h3 = values.allocate(30);               // reuses h1's slot with a *new* generation
// h3.index() == h1.index(), but h3.generation() != h1.generation();
// dereferencing the stale h1 now trips the use-after-free policy.
```

### RAII scope arena

```cpp
#include <memsafe/scope.hpp>

{
    memsafe::Scope scope;
    Widget* w = scope.create<Widget>(args...);   // raw pointer, owned by the arena
    // ... use w while the scope is alive ...
}                                                 // every created object destroyed in reverse order
```

Thread-safe variants (`SyncOwner`, `SyncRef`, `SyncMutRef`, `Arc`, `Mutex`) live in
`<memsafe/sync.hpp>` and mirror the above with atomic counters; e.g. `Mutex<T>::lock()` returns an
exclusive `MutRef<T>`.

## Core types

| Type | Header | Role |
|------|--------|------|
| `Owner<T>` | `owner.hpp` | Move-only unique owner; `noexcept` move; `borrow()` / `borrow_mut()` |
| `Ref<T>` / `MutRef<T>` | `owner.hpp` | Shared-immutable / exclusive-mutable borrows (`[[nodiscard]]`) |
| `Slot<T>` / `Handle<T>` | `handle.hpp` | Storage cell with atomic generation / index+generation token |
| `SlotMap<T, N>` | `handle.hpp` | Bounded, lock-free generational allocator (`allocate`/`get`/`deref`/`deallocate`) |
| `Scope` | `scope.hpp` | RAII arena; `create<T>(args…)` returns a scope-owned raw pointer |
| `SyncOwner<T>` / `SyncRef<T>` / `SyncMutRef<T>` | `sync.hpp` | Thread-safe ownership/borrows (atomic counters) |
| `Arc<T>` | `sync.hpp` | Atomically reference-counted shared owner |
| `Mutex<T>` | `sync.hpp` | Wraps a `T`; `lock()` yields an exclusive `MutRef<T>` |

## Configuration

Set these as preprocessor defines before including the headers (e.g. via your build system).

| Macro | Effect |
|-------|--------|
| `MEMSAFE_ON_VIOLATION` | Violation policy: `MEMSAFE_VIOLATION_ABORT` (default), `_THROW` (throws `memsafe::violation`), or `_HANDLER` (calls a user handler) |
| `MEMSAFE_RELEASE_CHECKS` | `0` compiles away all runtime borrow/generation checks for zero-overhead release builds |
| `MEMSAFE_CXX17_COMPAT` | `1` builds the C++17 subset (SFINAE instead of concepts; no `std::source_location`) |
| `MEMSAFE_BACKEND_CLANG` / `_GCC` / `_MSVC` | Compiler back-end (autodetected; manual override honored) |
| `MEMSAFE_BACKEND_CHERI` / `_RUSTY_CPP` | Optional analyzer/hardware back-ends (annotations only) |
| `MEMSAFE_BORROWS(x)` / `MEMSAFE_NODISCARD` | Annotation macros (e.g. Clang `lifetimebound`); no-ops without a back-end |

When a borrow/generation invariant is violated, the configured policy fires. Under `THROW` it raises
`memsafe::violation` (carrying kind, message, and source location); under `HANDLER` it calls the
function installed via `memsafe::set_violation_handler`; the default `ABORT` emits a diagnostic and
terminates rather than continuing into undefined behavior.

## Building & testing

The library needs no build, but the repo ships a self-contained, backend-agnostic test runner:

```bash
python tools/run_tests.py --backend auto
```

It auto-detects a backend (local toolchain → WSL → Docker → Podman), builds and runs every test and
example it discovers, and exits `0` if all selected lanes pass. The default lanes are
`debug`, `release`, `asan-ubsan`, and `cxx17`; optional lanes wire up the sanitizer matrix, property,
fuzz, concurrency, and performance categories. Full details — lanes, the drop-in contract, negative
compile tests, and backend selection — are in
**[documentation/BUILD_AND_VALIDATE.md](documentation/BUILD_AND_VALIDATE.md)**.

## Scope & non-goals

`memsafe` targets **partial** safety. Out of scope for v1: full Rust-style compile-time borrow
checking (a header-only library can't track lifetimes across arbitrary code), guaranteed data-race
freedom (use the `Sync*` types and `Mutex<T>` correctly), and unbounded/weak containers
(`GrowableSlotMap`, weak handles, typed `Region<Tag>`) — these are deferred to v1.1.
